# Правила безопасности репозитория

Перед написанием кода:

- Проверь, что есть `.gitignore`, `.env.example` и CI-проверка секретов.
- Никогда не клади `service_role`, пароли, строки подключения и приватные ключи в отслеживаемые Git-файлы.
- `config.js` содержит только публичный anon / publishable key. Это не секрет: защита данных — RLS и вход.
- Не читай, не печатай и не копируй значения из `.env*`, `*.pem`, `*.key`, `credentials*.json` без явного узкого разрешения.
- Считай `.gitignore` правилом для Git, а не границей конфиденциальности.
- Не ослабляй RLS (`using (true)` запрещён). Доступ только у участников household.
- Не добавляй пакеты с выдуманными именами и не запускай `curl | bash` / `npx -y` из непроверенных источников.
- Если секрет найден в чате, выводе или diff: остановись, замаскируй значение, предложи ротацию.
